# Captain preferences

- Model routing (adopted 2026-09-26, Kun's line-up x.com/kunchenguid/status/2103277022235766963): assign every worker through `config/crew-dispatch.json`, resolved by Jev with `bin/fm-dispatch-resolve.sh` on every intake (needs `TYPESAFE_API_KEY` in `.env`; x.com/kunchenguid/status/2100468943853085061). Buckets: planners/investigation -> Opus 5.5 xhigh; adversarial review -> GPT 6 Sol xhigh; implementers (Opus 5.5, GPT 6 Sol) -> medium; trivial fixes -> GPT 6 Luna; premium (Fable 5.1 / GPT 6 Astra) only with captain approval; budget fallbacks when subscription quota runs out: Muse Spark 1.3, DeepSeek V4 Flash (only once signed in). Judge by capability tier, never by vendor or harness: frontier work never goes to a weak model because of a harness preference.
- Route at task level, never per request (x.com/kunchenguid/status/2103895901140042044): a strong model first digs into the ask to judge its real complexity, then delegates substantial subtasks to models of fitting intelligence. Never switch a worker's model mid-session; prompt caching makes that more expensive than keeping the best model. Request-level routers are not a substitute.
- Effort is a ceiling, not a floor (x.com/kunchenguid/status/2103325882752598078): medium when the task is well defined, xhigh when it is not yet well defined; avoid low and max.
- Quota pacing (2026-09-27): use quota fully but steadily, so work never stops and the captain never waits for a reset. Pace every window, weekly included, toward a burn multiple of about 1x (`quota-axi --full` windows): the weekly allowance is the binding limit because one fully used 5-hour window costs roughly 13-17% of a week. Size concurrency to that pace (about one or two workers per provider on the current plans), backfill a slot only when pace allows, and prefer pausing work that has just started over work with invested context. Keep a 30% reserve floor as a safety net (quota watches via `bin/fm-procevent-quota.sh arm --provider <p> --threshold 30`, re-armed each session and after each fires); when one provider nears it, let running sessions finish and send new work to the provider with headroom. Never waste tokens: no mid-session model switches by choice, no needless relaunches, token-efficient briefs, and every deliverable meets the universal standard (`docs/UNIVERSAL-STANDARDS.md`) at the highest quality.
- Work end to end through the firstmate machinery (backlog, dispatch resolver, quota-axi, no-mistakes, supervision) rather than shortcuts.
- Keep these preferences in dotfiles (`home/firstmate/data/captain.md`, linked into `~/firstmate/data/`) so they survive a fresh install; edit them there and commit.
